# 改进与开发方向建议

> 面向“接下来做什么”的决策文档。问题清单与现状见 [`PROJECT_AUDIT.md`](PROJECT_AUDIT.md)；
> 任务化拆解与优先级见 [`ROADMAP.md`](ROADMAP.md)。
> 本文给出**方向级**建议，每个方向说明动机、做法、产出、代价与验收标准。

---

## 0. 结论先行

按“投入产出比”排序，推荐路线为：

```text
方向 A（仓库瘦身）  →  方向 B（内核正确性）  →  方向 C（实验可信度）  →  方向 D（算法深化）
   1–2 天                 1–2 周                1 周                   持续
```

- **A 必须先做**：不瘦身，后续所有 CI、检索、评审都在为 2 GB 的内核树买单。
- **B 是学术与工程的双重底线**：当前调度器在并发与内存分配上有真实风险，paper 里不宜省略。
- **C 决定论文能主张到什么程度**：现有结论含模型内建优势，需要外部证据支撑。
- **D 是“研究增量”**：前三个方向完成后，D 才有可靠的对照基线。

## 方向 A：仓库结构与依赖治理（P0，1–2 天）

### 动机

83,499 个内核文件 + 24 MB PPT + 多份 4 MB 级 PDF 全部受版本控制，
导致 clone 慢、检索噪音大、diff 不可读、CI 缓存困难。

### 候选做法（三选一）

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A1. 补丁化（推荐） | 只保留本项目改动的文件 + 一份 `patches/` 或 `git format-patch` 系列；内核源码改为文档中注明基线版本 | 仓库从 2 GB 降到 MB 级；评审聚焦真实改动 | 需要维护“如何套用补丁”的脚本；内核整树编译需先拉基线 |
| A2. Git submodule | 内核树作为 submodule 指向 linux 6.8 tag，另存改动补丁 | 保留完整树；基线明确 | submodule 对新手不友好；CI 需 `--recursive` |
| A3. Git LFS | 大二进制（pptx/pdf）走 LFS，内核树保留 | 改动最小 | 不解决内核树体积；需 LFS 配额 |

**推荐组合**：A1 + 大二进制迁移到 Release 附件。
具体可拆为：

1. 用 `git diff v6.8..HEAD -- linux-6.8-main/` 提取全部自有改动，生成
   `patches/0001-yat-casched-sched-class.patch` 等系列文件；
2. 保留 `linux-6.8-main/` 中**本项目新增**的测试脚本与文档到 `kernel-extras/`；
3. 在 `.gitignore` 中排除内核树（或按 A2 改为 submodule）；
4. `proj59.pptx` / `proj59.pdf` / 参考论文 PDF 移到 GitHub Release 或外部存储。

### 产出

- `patches/` 目录 + `apply-patches.sh`（可选 `--check` 干跑）
- `docs/DEVELOPMENT.md` 增加“从干净内核树还原工作区”的完整步骤
- 仓库体积下降一个数量级

### 验收

```bash
# 干净 clone 后
./scripts/apply-patches.sh --check      # 全部可应用
cd linux-6.8-main && make kernel/sched/yat_casched.o
```

### 风险

- 若历史提交仍需可复现，**不要**用 `git filter-repo` 重写历史；采取“新分支 + 新结构”的增量迁移。

## 方向 B：内核调度器正确性与并发安全（P0，1–2 周）

### 动机

[`PROJECT_AUDIT.md`](PROJECT_AUDIT.md) §2.3 中 K-01～K-09 是**真实缺陷**而非风格问题：
`GFP_ATOMIC` 分配可能失败、锁嵌套无统一顺序、CPU0 单点驱动、空回调导致语义不完整。
这些在论文/答辩中被追问时很难辩护。

### 建议拆解

| 子任务 | 做法 | 验收 |
|--------|------|------|
| B1. 消除热路径分配 | 把 `yat_calculate_recency` 中的 `kmalloc(NR_CPUS)` 改为栈上小数组（`NR_CPUS ≤ 64` 时）或预分配 per-cpu 缓冲 | 热路径无 `GFP_ATOMIC` |
| B2. 统一锁序 | 在文件顶部写明 `yat_pool_lock → global_dag_lock → dag->lock → rq->lock`，并用注释标注每个获取点；必要时拆分为更细粒度锁 | 静态审查 + lockdep 在 QEMU 中无告警 |
| B3. 去 CPU0 单点 | 就绪池改为 per-cpu 或按 NUMA 分片；`balance` 在本地 CPU 处理本地队列 | 8 核压测下 CPU0 不再 100% |
| B4. 补齐回调语义 | `set_cpus_allowed` 至少更新亲和掩码；`prio_changed` 触发重排；空回调加显式注释说明“故意为空” | 无空实现但无注释的函数 |
| B5. 移除热路径 `printk` | 改为 `trace_yat_casched_*` tracepoint 或 `pr_debug`（受 `CONFIG_DYNAMIC_DEBUG` 控制） | 入队路径无 `printk` |
| B6. CRP 真实实现 | 用环形缓冲记录最近 N 次访问时间戳，按 `now - last_access` 做指数衰减，替代线性 stub | 单元可测：给定访问序列输出预期 ratio |
| B7. 字段解耦 | 新增 `struct yat_entity` 字段承载自有状态，不再借用 `p->se.exec_start` / `rt_priority` | 代码中无 CFS 字段借用 |
| B8. 编号冲突预案 | 在 Kconfig/UAPI 注释中说明“8 为项目内约定，不与上游合并”；或改为可配置 | 文档明确风险 |

### 产出

- 一版可在 QEMU 中通过 `lockdep` + `KASAN` 启动的内核
- `docs/KERNEL_DESIGN.md`（新）：锁序图、状态机、热路径约束
- 针对 B1/B6 的内核内自测（可选 kunit）

### 验收

```bash
# 1) 编译
cd linux-6.8-main && make kernel/sched/yat_casched.o

# 2) QEMU + lockdep + KASAN 启动，运行 5 分钟负载
#    dmesg 中无 "possible circular locking dependency"、无 KASAN report

# 3) CPU0 占用率在 8 核并发下显著低于改造前
```

### 风险

- 锁粒度调整可能引入新的竞态：建议**先加注释与断言，再动结构**，每步单独提交。

## 方向 C：实验可信度（P1，约 1 周）

### 动机

现有结论（Makespan −11.66%、命中率 +30.21pp）来自**解析模型**，
且 CacheAware 的收益在模型中被内建（[`PROJECT_AUDIT.md`](PROJECT_AUDIT.md) §2.4 S-01/S-02）。
论文里若不加限定，容易被质疑“自己和自己比”。

### 建议拆解

| 子任务 | 做法 | 产出 |
|--------|------|------|
| C1. 公平基线 | 为 WFD 也接入同一套 `RecencyProfileReal` 执行时间模型（`ET = f(cache state)`），仅在**分配决策**上不同 | 两算法共享执行模型，差异只来自调度策略 |
| C2. 多 seed 统计 | 10 个种子 × 100 用例，报告均值 ± 95% CI，并做配对 t 检验 / Wilcoxon | `docs/EXPERIMENT_REPORT.md` 增补统计节 |
| C3. 指标解耦 | 用枚举/接口替代算法名字符串分支；`MetricProvider` 由算法实现提供 | 重命名不再影响指标 |
| C4. 真实 trace | 接入至少一组公开 trace（如 PARSEC 摘要或 SDC）或将合成任务标定为实测分布 | 一组真实负载结果 |
| C5. DAG 支持 | 为 `Node` 增加前驱列表，模拟通信开销与就绪判定 | 支持 DAG 任务的实验结果 |
| C6. 敏感度扫描 | 扫描缓存收益权重（0.40）与敏感度阈值，输出热力图 | 一张参数敏感度图，支撑“权重可自适应”的论点 |

### 产出

- 更新的 [`EXPERIMENT_REPORT.md`](EXPERIMENT_REPORT.md)（含 CI、显著性、公平基线说明）
- `simulator/` 中 `MetricProvider` 抽象 + 多 seed 运行脚本
- 一张参数敏感度热力图

### 验收

```bash
make -C simulator test          # 既有 102 断言仍通过（重命名相关断言需同步更新）
make -C simulator run-multiseed # 新增目标：10 seed 批量
```

> 注意：C3 会触碰 `[5]` 边界测试中固化“命名匹配”的断言，
> 这是**有意的行为变更**，需同步更新测试与文档说明。

### 风险

- 若 C1 让 WFD 也获得缓存收益，现行“+30pp”结论会大幅缩水——**这是好事**，应在论文中如实呈现。

## 方向 D：算法与研究深化（P2，持续）

> **2026-10 更新（C1 公平基线跑完之后）**：本节 D1–D7 的排序基于「先调算法」的假设，
> 已被实测推翻。公平口径下 Makespan 配对均值仅 **+0.39%**、95% CI 跨 0，
> 且机制审计显示 **40/60 个任务落 L3（系数 0.95），模型收益天花板本身只有约 5%**。
> 因此 [`ROADMAP.md`](ROADMAP.md) §4 已重排为 **D1' 真实硬件代价模型 → D2' trace 负载保真
> → D8' 仿真↔内核一致性**，把度量修好之后再启动本节的参数/算法类方向。
> 本节保留原有动机与风险分析，作为这些方向的详细说明。

前三个方向完成后，可在可靠基线上做研究增量。按“可发表性 / 实现成本”排序：

### D1. 自适应缓存热度窗口（高性价比）

现状是固定 10 ms / 固定窗口（初赛版）或线性 stub（决赛版）。
做法：以任务的历史迁移间隔分布为依据，动态调整 `cache_hot_window`，
并给出稳定性分析（避免窗口抖动）。

- 产出：一个新参数 + 消融实验
- 风险：窗口自适应本身可能引入振荡，需要滞回（hysteresis）

### D2. 数据驱动的 CRP（中）

用模拟器/真实 trace 拟合“重用距离 → 命中率”曲线，替代手工系数
（L1 ×0.8、L2 ×0.9 …）。可用简单的分段线性或小型回归模型。

- 产出：CRP 参数由数据拟合得到，附拟合优度
- 风险：过拟合到特定负载，需要交叉验证

### D3. 过载区权重自适应（中，直接回应现有 4 例失败）

现有失败案例全部在 U ≥ 1.0，且推测原因是缓存收益权重（0.40）过高。
做法：当 `nr_running` 或系统利用率超过阈值时，平滑下调缓存权重、上调负载均衡权重。

- 产出：消除 case 57 类退化；给出权重调度曲线
- 风险：阈值需要标定，避免轻载时误触发

### D4. NUMA 感知（中高成本）

把“同核缓存亲和”扩展为“同 NUMA 节点优先”，跨节点迁移代价显式建模。

- 产出：NUMA 拓扑建模 + 跨节点迁移惩罚
- 风险：需要多路环境或可信的 NUMA 模拟

### D5. 与 EAS / schedutil 协同（高成本）

在能效维度上做联合优化（频率 + 核选择）。

- 产出：能耗指标与能效对比
- 风险：需真实硬件功耗测量，模拟器难以支撑

### D6. 模拟器 ↔ 内核一致性验证（高价值，中等成本）

把模拟器的分配决策与内核调度日志做**逐决策对齐**：
同一组任务/参数下，模拟器输出的 `(job, core)` 序列应与内核 trace 一致。

- 产出：一致性检查脚本 + 差异报告
- 价值：这是把“模拟器结论”提升为“内核行为”的关键桥梁
- 风险：内核时序与模拟器离散事件模型存在天然差异，需定义“可接受的等价”

### D7. 机器学习辅助调度（探索性）

用轻量模型（决策树/小型 MLP）预测“迁移收益”，替代手工评分函数。

- 产出：可行性验证 + 与手工权重的对比
- 风险：可解释性与内核内推理成本；不建议作为主线

## 1. 不建议做的事

| 事项 | 原因 |
|------|------|
| 用 `git filter-repo` 重写历史来删大文件 | 破坏可复现性；应增量迁移到新结构 |
| 直接把调度类编号改成上游未占用值 | 上游编号动态变化，且本项目不计划合并；注释说明即可 |
| 在没有公平基线前继续调大缓存权重 | 只是放大模型内建优势，不构成证据 |
| 为模拟器引入 Spring 等重框架 | 与“轻量可复现”目标冲突；Maven/Gradle 足够 |
